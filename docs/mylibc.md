# mylibc

標準ライブラリのサブセットです。
`malloc` は K&R 8.7 から、文字列関数は標準の仕様から起こしました。

---

## 置き換えの範囲

libc の関数は、性質で 2種類に分かれます。

| | 例 | 扱い |
| :--- | :--- | :--- |
| システムコールの単純なラッパー | `read` `write` `open` `socket` `fork` `mmap` | 置き換えない。中に計算が無く、書いたところで生の syscall を呼ぶだけになる |
| 純粋な計算 | `str*` `malloc` `printf` 系 | 中にアルゴリズムがある。ここを置き換えた |

後者のうち、httpd が実際に呼んでいるものだけを書きました。
httpd が使う文字列操作は全て置き換えました。

---

## 実装した関数

`mylibc/my_string.c`

| | 仕様 |
| :--- | :--- |
| `my_strlen` | 終端の `'\0'` を含まない長さを返す |
| `my_strcmp` | 先に渡したほうが小さければ負、大きければ正、等しければ 0 を返す |
| `my_strncmp` | 先頭 n 文字までを比較する |
| `my_strcasecmp` | A-Z と a-z を同じものとして比べる |
| `my_strchr` | 探す文字が最初に現れた位置を返す。無ければ NULL。終端の `'\0'` も検索の対象 |
| `my_strrchr` | 探す文字が最後に現れた位置を返す |
| `my_strstr` | 探す文字列が最初に現れた位置を返す。空文字列は先頭に一致 |
| `my_strspn` | 先頭から、指定した文字の集合に含まれる文字が続く長さを返す |

`mylibc/my_malloc.c` — `my_malloc` と `my_free`。
K&R 8.7 のアロケータ。

`mylibc/my_snprintf.c` — `my_snprintf` と `my_vsnprintf`。
httpd が使う書式は `%s` `%d` `%lld` `%%` の 4つだけなので、ほかは実装していません。
幅と精度の指定も使わないので、解釈しません。

## `char` の符号は実装依存

`my_strcmp` を素直に書くと、環境によって答えが変わります。

```c
/* 悪い */  return *a - *b;
/* 良い */  return (unsigned char)*a - (unsigned char)*b;
```

```
   0x80 と 0x01 を比べる
   char が符号なし (aarch64 Linux)     128 - 1 = 127   → 正
   char が符号あり (x86 Linux)        -128 - 1 = -129 → 負
```

C は `char` が符号付きか符号なしかを決めていません。
一方で `strcmp` は「符号なし文字として比較する」と決まっているので、キャストを明示します。

## K&R 8.7 のアロケータ

アルゴリズムは K&R 8.7 のものです。
このアルゴリズムの要点は、空きリストを大きさ順ではなくアドレスの小さい順に並べることです。

要求に合う空きを早く見つけるだけなら、大きさ順のほうが有利です。
ただしその並びでは、メモリ上で隣り合っている空き同士がリストの上では離れてしまいます。
隣かどうかを調べるのに、リスト全体を見て回ることになります。

アドレス順にしておくと、挿す位置を探し終えた時点で前後の空きが両方とも手元にあります。
`my_free` が「直前の空きの終わり == 自分の先頭」を 1回確かめるだけで繋げられるのは、そのためです。

```mermaid
flowchart LR
    subgraph before["my_free(X) の前"]
        direction LR
        A["空き A"] --- X["使用中 X"] --- B["空き B"] --- Y["使用中 Y"]
    end
    subgraph after["my_free(X) の後"]
        direction LR
        M["空き A + X + B"] --- Y2["使用中 Y"]
    end
    before -- "X を解放" --> after
    style A fill:#e8f5e9,stroke:#43a047
    style B fill:#e8f5e9,stroke:#43a047
    style M fill:#e8f5e9,stroke:#43a047
```

アドレスの小さい順なので、`A` の終わりが `X` の先頭、`X` の終わりが `B` の先頭であることは 1回の比較で分かります。
あとは 3つを 1つに繋ぐだけです。

繋げないままだと、合計では足りているのに連続した空きが取れなくなります。
速さのためではなく、断片化を抑えるための設計です。

K&R から変えたのは領域の取り方だけです。
`sbrk` ではなく `mmap` を使っています。
`sbrk` はヒープの先端を伸び縮みさせるだけなので、自分が確保した場所を指定して返せません。

管理情報の置き方と、大きさ 0 の番兵を置く理由はソースのコメントに書いてあります。

フリーリストが共有状態なので、スレッド安全ではありません。
httpd は 1プロセス 1スレッドで使うので、問題にはなりません。

## テスト

K&R にテストは載っていません。
ここから先は自分で決めた部分です。

確かめたいものが違えば、方法も変わります。

```
my_strcmp / my_snprintf →「標準と同じ答えを返すか」で決まる      → 差分テスト
my_malloc               → 返るアドレスは実装ごとに違う。比べられない → 性質テスト
```

文字列関数と `my_snprintf` は、標準ライブラリを正解役にして総当たりで突き合わせます。
期待値を自分で書くと、実装と同じ思い込みが入るからです。
`my_snprintf` は出力だけでなく、収まらなかったときの戻り値も見ます。
`response.c` が溢れの検出に使っているためです。

`my_malloc` でいちばん効いているのが併合のテストです。

```
1000バイト × 32個 を確保  →  全部 free  →  16000バイトを要求
```

1個分では到底足りず、半数以上が繋がって初めて届く大きさです。
断片化した後では確かめようがないので、このテストだけは一番先に呼んでいます。

配り直しのテストは、配られるアドレスの種類で見ています。

```
配り直している  →  同じ空きが返り続けるので、アドレスは数種類で頭打ち
していない      →  arena を取り足し続け、毎回新しいアドレスが出る
```

`/proc/self/statm` で OS から取ったページ数を読む手もありますが、
`/proc` の無い環境では黙って合格してしまうため、アドレスを見る形にしました。

## 置き換えの例外

httpd が呼んでいるのに、libc のまま残した関数です。
なぜ置き換えの対象にしなかったかを書いておきます。

| | なぜ置き換えないか |
| :--- | :--- |
| `fprintf` | 書式の解釈は `my_snprintf` と同じだが、その先がバッファリングと `FILE` の話になる。httpd はバッファを自前で持ち、ソケットも生の fd で扱うので、`FILE` の利用者がいない |
| `strerror` | errno と文字列の対応表で、学べるのが表引きだけ。しかも自分が出す errno しか埋められないので、必然的に libc より悪いものになる |
| `realpath` | 中で `lstat` と `readlink` を繰り返す。純粋な計算ではなくシステムコールの側 |
| `setenv` | `environ` の所有権 (誰が確保し、誰が解放するか) があいまいで、得るものの割に落とし穴が多い |
